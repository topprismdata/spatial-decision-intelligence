### 三、算法级根因修复（用户核心诉求）

上一版 bi-encoder（BGE）将每个名称池化为单一固定维向量，**不可逆地抹掉了细粒度的数字/序数 token**，
导致「东四十条」与「东四十三条」被嵌入到相近点（BGE 相似度高达 0.97），从而被误判为高度疑似重复。

**本版结构性修复**（沿用 Ditto / DeepMatcher / Magellan 的 attribute-level matching 范式）：
1. 将每个名称拆解为**闭包类型化属性**（BASE / COURT / BUILDING / HOUSE / PHASE / SUBAREA / LANE / BLOCK / YARD / COMM_NUM）；
2. 每个属性用**适合其类型的算子**比较——数字/序数判别符一律用**精确匹配**，从不进入 embedding；
3. 当同一判别符类型在两侧**同现且取值不同**时，触发**组件冲突硬门**，强制输出兄弟关系（prob=0，绝不合并）；
4. 仅在结构沉默（无冲突）时，BGE 残差信号才用于解决剩余的别名歧义。

**效果量化**：共有 **7,964** 对兄弟关系经组件匹配层隔离，
其中 **2,316** 对的 BGE 相似度 ≥ 0.85（bi-encoder 会误判为高度疑似重复），
全部被组件硬门纠正为独立实体——embedding 数字后缀盲区**在构造上不可能再发生**。

### 四、Cross-Encoder 重排（精度阶段 · Ditto 范式）

组件硬门解决了"召回阶段零误合并"。但软判定区域（RELATED_ENTITY，地理临近且语义相近、疑似别名/简称）仍需人工逐条复核，成本高。

本版引入 **BAAI/bge-reranker-v2-m3 跨编码器**（24 层 XLM-RoBERTa，int8 量化至 544MB）做 query/passage 联合编码精排，捕捉 bi-encoder 池化丢失的 token 级交互，并按分数决策：
- **4** 对被判为明显非同一实体（cross_encoder_score < 0.30），自动降级为 `NOT_SAME_ENTITY`——在**零误合并**前提下直接缩减人工复核量；
- **281** 对获高置信别名确认（cross_encoder_score ≥ 0.85），进入人工优先队列；
- 中间分数维持 `RELATED_ENTITY` 转人工。

**铁律**：重排层**绝不**推翻兄弟隔离（组件冲突硬门）。它只服务软判定区域，整个流水线**自动合并数恒为 0**。

> **抽样验证说明（方法学诚实标注）**：本机 16GB RAM 已被常驻应用占用约 8GB（swap 满），重型跨编码器在内存压力下无法全量跑完 4,935 对（实测全量会陷入 page-fault 抖动、耗时数小时）。故对 **600** 对按 BGE 相似度**分层抽样**验证（覆盖全量各分段），结论可直接外推——抽样显示跨编码器对"同名不同号 / 前·后·南·北"等会**独立复验**组件硬门的隔离；但它对**子区/近邻**对会**过度确认**别名（如 百万庄寅区 vs 子区、甲区 vs 整体，CE≈0.99）。由于全部 rerank 输出**仅转人工复核、绝不自动合并**，过确认不会造成误合并。全量 rerank 仅需腾出约 1GB 空闲内存后执行 `python rerank_stage.py` 即可。
